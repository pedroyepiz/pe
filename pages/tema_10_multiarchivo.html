10.1 · ¿Qué es un programa multiarchivo?

Un programa multiarchivo distribuye su código en varios archivos fuente y de cabecera. Todos forman parte del mismo proyecto y, al compilarse y enlazarse, producen un único programa ejecutable.

📄

main.c

Contiene normalmente el punto de entrada y coordina el flujo principal.

📘

funciones.h

Declara prototipos, tipos, macros y elementos compartidos.

⚙️

funciones.c

Implementa el cuerpo de las funciones declaradas en el encabezado.

🔗

Enlazador

Une los módulos compilados para generar el ejecutable final.

💡
VENTAJA PRINCIPAL
Separar el código permite organizar mejor un proyecto grande, reutilizar funciones, facilitar el mantenimiento y trabajar por módulos.

10.2 · Estructura típica de un proyecto

main.c Usa las funciones del proyecto.
funciones.h Declara la interfaz.
funciones.c Implementa la lógica.
funciones.h
#ifndef FUNCIONES_H
#define FUNCIONES_H

int suma(int a, int b);
void menu(void);

#endif
funciones.c
#include <stdio.h>
#include "funciones.h"

int suma(int a, int b)
{
    return a + b;
}

void menu(void)
{
    printf("MENU PRINCIPAL\n");
}
main.c
#include <stdio.h>
#include "funciones.h"

int main(void)
{
    menu();
    printf("RESULTADO: %d\n", suma(3, 5));

    return 0;
}

10.3 · ¿Cómo se compilan varios archivos?

En un proyecto multiarchivo, cada archivo fuente puede compilarse por separado y después enlazarse con los demás. Un compilador como GCC también permite realizar ambos pasos con un solo comando.

Terminal · GCC
gcc main.c funciones.c -o programa
El archivo .h normalmente se incluye mediante #include; los archivos .c son los que se compilan y enlazan para formar el ejecutable.

10.4 · Ejecución de archivos externos con system()

El material de clase amplía el tema multiarchivo mostrando cómo un programa en C puede pedir al sistema operativo que ejecute otro programa, comando o script. Para ello se utiliza system(), declarada en <stdlib.h>.

☎️
Analogía del teléfono: el programa principal necesita un servicio externo. En lugar de hacerlo directamente, “llama” al sistema operativo mediante system() y le entrega el comando que desea ejecutar.
int system(const char *command);
system_basico.c
#include <stdlib.h>

int main(void)
{
    system("dir");      /* Windows */
    /* system("ls"); */ /* Linux / macOS */

    return 0;
}

10.5 · ¿Para qué enviar parámetros?

Un programa externo suele necesitar datos. Si tenemos un ejecutable llamado calculadora.exe, podemos ejecutarlo con información adicional:

Sin parámetros calculadora.exe El programa se ejecuta, pero no recibe los números que debe procesar.
Con parámetros calculadora.exe 50 100 El programa externo puede interpretar 50 y 100 como argumentos.
🧩
El comando completo que recibe system() es una cadena. Por eso, si los valores vienen de variables, debemos construir primero esa cadena.

10.6 · Construcción de comandos con variables

El material de clase utiliza sprintf() para escribir dentro de una cadena el nombre del ejecutable y los parámetros que deseamos enviar.

construir_comando.c
char comando[100];

sprintf(comando,
        "nombre_programa.exe param1 param2");

int resultado = system(comando);
Si un parámetro contiene espacios, debe enviarse entre comillas. Por ejemplo: prog.exe "Baja California". De lo contrario, el sistema operativo puede interpretarlo como varios argumentos separados.

10.7 · Ejemplo práctico completo

Supongamos que existe un programa externo llamado saludo.exe que recibe un nombre y una edad. El programa principal construye el comando y lo ejecuta.

main.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char nombre[50];
    int edad;
    char comando[150];
    int estado_retorno;

    printf("INGRESE NOMBRE: ");
    scanf("%49s", nombre);

    printf("INGRESE EDAD: ");
    scanf("%d", &edad);

    sprintf(comando,
            "saludo.exe \"%s\" %d",
            nombre,
            edad);

    printf("\nEJECUTANDO COMANDO: %s\n",
           comando);

    estado_retorno = system(comando);

    if (estado_retorno == 0)
    {
        printf("EL PROGRAMA EXTERNO TERMINÓ CON ÉXITO.\n");
    }
    else
    {
        printf("EL PROGRAMA EXTERNO TERMINÓ CON CÓDIGO: %d\n",
               estado_retorno);
    }

    return 0;
}
En este ejemplo, sprintf() no imprime en pantalla: escribe el texto formateado dentro de la variable comando.

10.8 · ¿Qué devuelve realmente system()?

Un punto importante del material es que el valor devuelto por system() no representa la cantidad de argumentos. Representa información relacionada con el estado de terminación del comando o programa ejecutado.

❌

Interpretación incorrecta

system() no sirve para contar los argumentos enviados.

✅

Interpretación correcta

El valor de retorno se usa para conocer el resultado de la ejecución del comando.

📌
Para conocer cuántos argumentos recibió nuestro propio programa, usamos argc. Para conocer el resultado del programa externo, analizamos el valor devuelto por system().

10.9 · Buenas prácticas, seguridad y compatibilidad

1 · Usa comillas

Protege argumentos con espacios: "Baja California".

2 · Valida entradas

No construyas comandos a partir de texto del usuario sin verificarlo.

3 · Evita comandos arbitrarios

Permitir al usuario controlar el comando puede representar un riesgo grave.

4 · Revisa el retorno

No asumas que el programa externo se ejecutó correctamente.

5 · Considera el sistema operativo

Windows, Linux y macOS tienen comandos y rutas diferentes.

6 · Usa rutas claras

Si el ejecutable no está en la carpeta esperada, especifica una ruta válida.

Seguridad: system() debe usarse con cuidado. Si un usuario puede introducir directamente el contenido del comando, podría ejecutar acciones no deseadas. En proyectos reales, evita construir comandos con entrada no confiable.

10.10 · Ejecución de archivos externos

Además de ejecutar un programa compilado, system() puede invocar scripts o comandos del sistema. El material propone como práctica crear un archivo externo y enviarle parámetros desde C.

prueba.bat · Windows
@echo off
echo HOLA DESDE EL ARCHIVO EXTERNO %1 %2
main.c
#include <stdlib.h>

int main(void)
{
    system("prueba.bat Juan Perez");
    return 0;
}
🔌
CONEXIÓN ENTRE PROGRAMAS
Con esta técnica, un programa en C puede coordinarse con ejecutables, scripts y utilidades externas. Esto amplía mucho lo que puede hacer, pero también exige mayor cuidado con rutas, parámetros y seguridad.

En resumen: multiarchivo vs ejecución externa

Concepto Multiarchivo Ejecución externa
Objetivo Organizar un mismo programa en varios archivos. Solicitar al sistema operativo ejecutar otro programa o comando.
Archivos .c, .h y módulos compilados. .exe, scripts, comandos u otras herramientas.
Herramienta principal Compilación + enlazado. system() de <stdlib.h>.
Relación Los módulos terminan formando un solo ejecutable. El programa ejecuta otro proceso externo.

EN RESUMEN
La programación multiarchivo organiza un proyecto en módulos y separa interfaz, implementación y programa principal. La función system() agrega una capacidad diferente: permite solicitar al sistema operativo la ejecución de un comando o programa externo. Ambas técnicas ayudan a construir programas más organizados, reutilizables y conectados con su entorno.
