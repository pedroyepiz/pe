Solución recursiva

Resolver un problema haciendo que una función se llame a sí misma, reduciendo el problema hasta alcanzar un caso base.

“Una función recursiva debe saber cuándo continuar y, sobre todo, cuándo detenerse.”
IDEA CENTRAL

Dividir el problema hasta llegar a una solución simple

La recursión es una técnica en la que una función se llama a sí misma para resolver una versión más pequeña del mismo problema. Cada llamada debe acercarse al caso base, que es la condición que detiene la recursión.

9.1 · ¿Qué es la recursión?

Una función es recursiva cuando, directa o indirectamente, vuelve a invocarse a sí misma. La idea es reemplazar un problema grande por una versión más pequeña del mismo problema.

🔁

Llamada recursiva

La función se vuelve a llamar con datos más pequeños o más cercanos al objetivo.

🛑

Caso base

Es la condición que evita que la función siga llamándose indefinidamente.

📉

Reducción

Cada llamada debe reducir el problema para garantizar que el caso base será alcanzado.

🧠

Abstracción

Permite expresar algunos algoritmos complejos de forma compacta y cercana a su definición matemática.

💡
REGLA FUNDAMENTAL
Toda función recursiva correcta necesita dos partes: un caso base y una llamada recursiva que se acerque a ese caso base.

9.2 · ¿Cómo funciona?

Cuando una función recursiva se llama a sí misma, la llamada actual queda suspendida temporalmente mientras espera el resultado de la siguiente llamada. Esto se repite hasta llegar al caso base.

1Problema originalEjemplo: factorial(4)
2Reduce4 × factorial(3)
3Reduce otra vez3 × factorial(2)
4Caso basefactorial(0) = 1
🪆
Analogía de las muñecas rusas: cada muñeca contiene otra más pequeña. Llegas a la más pequeña y entonces comienzas a cerrar una por una. En recursión, primero se hacen las llamadas y después se van resolviendo al regresar.

9.3 · ¿Cómo se detiene la recursión?

La recursión se detiene mediante el caso base. Es una condición que puede resolverse directamente sin volver a llamar a la función.

forma_general.c
tipo funcion(parametro)
{
    if (caso_base)
    {
        return resultado_directo;
    }

    return operacion(
        funcion(problema_mas_pequeno)
    );
}
Si no existe un caso base o nunca se alcanza: la función seguirá creando llamadas hasta agotar la memoria disponible para la pila de llamadas, produciendo normalmente un stack overflow.

9.4 · ¿Cómo maneja la memoria?

Cada llamada a una función recursiva genera un nuevo marco de activación en la pila de llamadas (call stack). Allí se conservan, entre otros datos, los parámetros, variables locales y la información necesaria para regresar a la llamada anterior.

Pila durante factorial(4)
factorial(0) → devuelve 1
factorial(1) → espera resultado
factorial(2) → espera resultado
factorial(3) → espera resultado
factorial(4) → espera resultado
main()
⬆️

Al llamar

Se agrega un nuevo marco a la pila. Las llamadas anteriores quedan esperando.

⬇️

Al regresar

Los marcos se retiran en orden inverso y cada llamada recibe el resultado que esperaba.

📚
LIFO
La pila de llamadas trabaja como una pila: la última llamada que entra es la primera que termina.

9.5 · ¿Cómo estructurar una función recursiva?

1 · Define el caso base

Identifica el problema más pequeño que puede resolverse directamente.

2 · Reduce el problema

Modifica el parámetro para acercarte claramente al caso base.

3 · Realiza la llamada recursiva

La función vuelve a llamarse con el problema reducido.

4 · Combina el resultado

Usa el valor regresado por la llamada recursiva para construir la solución actual.

5 · Verifica el avance

Asegúrate de que cada llamada esté más cerca de terminar.

6 · Evalúa si conviene

No todo problema necesita recursión; a veces una solución iterativa es más eficiente.

Pregunta que debes hacerte: “¿puedo expresar la solución de este problema usando una versión más pequeña del mismo problema?” Si la respuesta es sí, probablemente existe una formulación recursiva natural.

9.6 · Ejemplo clásico: factorial

El factorial de un número entero no negativo se define como: n! = n × (n-1) × (n-2) ... × 1. Además, por definición, 0! = 1.

factorial_recursivo.c
#include <stdio.h>

long long factorial(int n)
{
    if (n == 0 || n == 1)
    {
        return 1;
    }

    return n * factorial(n - 1);
}

int main(void)
{
    int n = 5;

    printf("%d! = %lld\n", n, factorial(n));

    return 0;
}

Traza de factorial(4)

factorial(4)
= 4 * factorial(3)
= 4 * 3 * factorial(2)
= 4 * 3 * 2 * factorial(1)
= 4 * 3 * 2 * 1
= 24

9.7 · Fibonacci: ejemplo de recursión poco práctica

La sucesión de Fibonacci se define con dos casos base: F(0)=0 y F(1)=1. Los demás términos se calculan como: F(n)=F(n-1)+F(n-2).

fibonacci_recursivo.c
#include <stdio.h>

long long fibonacci(int n)
{
    if (n == 0)
    {
        return 0;
    }

    if (n == 1)
    {
        return 1;
    }

    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main(void)
{
    printf("F(10) = %lld\n", fibonacci(10));
    return 0;
}
F(5)
F(4)
F(3)
Muchas llamadas se repiten: F(3), F(2), F(1) y otras se calculan varias veces.
¿Por qué no es práctico así?
La versión recursiva directa de Fibonacci repite una gran cantidad de cálculos. El número de llamadas crece rápidamente y, además, cada llamada utiliza espacio en la pila. Por eso puede consumir mucho tiempo y memoria comparada con una solución iterativa o una versión con memoización.
Versión iterativa
long long fibonacci_iterativo(int n)
{
    long long a = 0;
    long long b = 1;

    for (int i = 0; i < n; i++)
    {
        long long temp = a + b;
        a = b;
        b = temp;
    }

    return a;
}
⚖️

Lección importante

Que un problema tenga una definición recursiva no significa que la implementación recursiva ingenua sea siempre la mejor opción.

9.9 · Ventajas y desventajas

✅ Ventajas

  • Puede producir soluciones más cortas y elegantes.
  • Es natural para árboles y estructuras jerárquicas.
  • Se adapta muy bien a algoritmos de dividir y vencer.
  • Permite expresar directamente ciertas definiciones matemáticas.
  • Puede mejorar la claridad conceptual de algunos algoritmos.

⚠️ Desventajas

  • Cada llamada consume espacio en la pila.
  • Puede provocar desbordamiento de pila si la profundidad es grande.
  • Puede ser más lenta por el costo de las llamadas a función.
  • Es más difícil de depurar para quien apenas aprende el concepto.
  • Una mala formulación puede repetir trabajo de manera excesiva, como Fibonacci ingenuo.
🎯
CRITERIO DE ELECCIÓN
Usa recursión cuando simplifique realmente el problema y la profundidad de llamadas sea razonable. Si una solución iterativa es más simple y eficiente, no es obligatorio usar recursión.

Errores comunes

1. Olvidar el caso base.
2. Tener un caso base que nunca se alcanza.
3. No reducir el problema en cada llamada.
4. Usar recursión en problemas donde repite trabajo innecesario.
5. No considerar la profundidad máxima de la pila.
6. Confundir la llamada recursiva con un ciclo normal.

EN RESUMEN
La recursión permite resolver un problema usando versiones más pequeñas del mismo problema. Toda solución recursiva necesita un caso base, una reducción clara y una llamada recursiva. Cada llamada utiliza espacio en la pila, por lo que debes valorar siempre su claridad frente a su costo en tiempo y memoria.
